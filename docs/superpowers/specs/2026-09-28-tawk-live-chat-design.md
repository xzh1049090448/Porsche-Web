# Tawk.to 实时聊天全站接入设计

日期：2026-09-28  
状态：已获产品确认，待实施

## 背景

产品需要接入 Tawk.to 实时客服。项目是 Vue 3 + Vite 单页应用，所有公共页面、认证页面和控制台页面都由仓库根目录的 `index.html` 启动。用户选择直接嵌入 Tawk.to 官方脚本，并确认开发、预览和生产环境都加载真实聊天服务。

## 目标

- 在全站提供同一个 Tawk.to 实时聊天入口。
- 覆盖现有公共页、登录/注册页和登录后的全部控制台路由。
- 后续新增 Vue 页面或路由时自动继承实时聊天，无需开发者逐页接入。
- Tawk.to 加载失败时不阻断应用启动和页面交互。
- 不主动向 Tawk.to 传递用户资料、认证信息或业务数据。

## 非目标

- 不实现自建聊天后端、聊天记录同步或客服工单系统。
- 不根据用户角色、路由、语言或主题动态配置 Tawk.to。
- 不增加环境开关、Cookie 同意流程或后台管理开关。
- 不调用 Tawk.to 身份识别 API，也不传递用户名、GUID、Token、手机号或其他账户字段。

## 接入方式

在根目录 `index.html` 的 `</body>` 前加入用户提供的官方嵌入代码。脚本位于现有 `/src/main.js` 模块入口之后，异步创建并插入以下远程脚本：

```text
https://embed.tawk.to/6aba033429f257344364f946/1k3j9p1b0
```

保留官方代码的全局变量、`async=true`、`charset="UTF-8"` 和 `crossorigin="*"` 属性。远程脚本异步执行，不进入 Vue 启动依赖链；Tawk.to 网络错误不会阻止 `#app` 挂载。

## 全路由与未来页面保证

`index.html` 是生产构建和开发服务器唯一的 SPA HTML 入口。Vue Router 的所有现有路由以及未来新增路由都复用该文档，因此聊天脚本只需在这个入口保留一份。

实现和测试禁止把 Tawk.to 代码复制到 `PublicLayout`、`MainLayout` 或具体页面组件。这样新增页面时不需要额外清单、组件引用或手工接入，也不会出现不同路由重复创建聊天窗口的问题。

若未来项目增加独立 HTML 入口、多页面构建或脱离当前 SPA 的静态页面，该新入口必须显式复用同一嵌入片段；本次设计不为尚不存在的多页面架构增加抽象层。

## 数据与安全边界

- 浏览器会直接连接 Tawk.to 域名；第三方网络请求是方案 B 的预期行为。
- 本地开发、预览和生产构建均会加载该脚本。
- 页面只加载用户给定的固定 Tawk.to property/widget 地址。
- 本次不读取 Pinia、localStorage、Cookie 或页面中的认证状态，不设置 `Tawk_API.visitor`，不把私有数据发送给第三方。
- 不为远程脚本增加同步等待、失败重试或影响应用的错误处理。

## 验证设计

新增静态契约测试，至少验证：

1. `index.html` 中只存在一份 Tawk.to 嵌入脚本。
2. 固定远程地址、`async`、`UTF-8` 和 `crossorigin="*"` 保持一致。
3. 嵌入代码位于现有 Vite 应用入口之后、`</body>` 之前。
4. Tawk.to 代码不出现在公共布局、控制台布局或具体页面组件中。
5. 全量前端测试通过。
6. `VITE_USE_MOCK=false npm run build` 通过，并在生成的 `dist/index.html` 中保留唯一嵌入代码。

浏览器验证使用请求拦截阻止真实 Tawk.to 网络访问，分别打开公共路由、登录路由和控制台路由，确认应用仍能挂载且不会重复插入嵌入代码。测试不得产生真实客服会话。

## 验收标准

- 构建产物在任意现有 SPA 路由加载时都会执行同一份 Tawk.to 官方嵌入代码。
- 后续仅新增 Vue Router 页面时无需修改实时聊天代码。
- 页面应用不等待远程脚本，第三方加载失败不影响主要功能。
- 未新增用户身份映射、业务数据传输、环境开关、后端接口或依赖。
