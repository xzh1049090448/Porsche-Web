# Gateway API Key 管理页设计

## 目标与范围

在 `llm-platform` 用户端新增独立的“API 密钥”导航页，接入 Go 网关已实现的 `/api/v1/tokens` 接口。用户可创建、查看、编辑和撤销自己拥有的 Gateway API Token，并能了解 Token 的状态、模型访问范围、IP 白名单和到期时间。

本轮只使用已落地的 Token CRUD、模型 ACL、IP 白名单、状态和到期能力；不展示或模拟渠道、路由、用量审计、配额、账务、租户或项目数据。

## 页面与路由

- 新增路由 `/api-keys`，使用既有 `MainLayout` 和认证守卫。
- 主导航新增“API 密钥”入口，沿用现有桌面和移动端导航模式。
- 页面采用“概览 + 列表”布局：顶部展示已启用、已撤销、即将过期三个本地派生的状态卡；下方为 Token 列表。
- 不显示后端当前未提供的真实用量、最后使用时间或渠道信息。

## API 边界

新增 `src/api/gatewayTokens.js`，通过既有 Axios `request` 调用：

- `GET /api/v1/tokens`
- `POST /api/v1/tokens`
- `GET /api/v1/tokens/{id}`
- `PATCH /api/v1/tokens/{id}`
- `POST /api/v1/tokens/{id}/revoke`

复用请求拦截器中的 JWT；完整 Gateway Token 不写入 Pinia、localStorage、URL、日志或错误提示。

## 交互设计

### 列表与概览

表格列为：名称、Token 前缀、允许模型、IP 白名单摘要、状态、到期时间、创建时间和操作。空的允许模型表示全部模型，空的 IP 白名单表示不限制来源 IP。状态卡完全由已加载列表派生；“即将过期”定义为未来 7 天内到期且仍未撤销的 Token。

### 创建

“创建密钥”打开 Element Plus 抽屉，填写名称、模型多选、IP/CIDR 白名单和可选 RFC3339 到期时间。成功后关闭抽屉并显示一个不可关闭的安全确认弹窗：完整 Token 仅在该弹窗展示一次，用户可复制，且必须点击“我已安全保存”才可结束。

### 编辑与撤销

编辑复用抽屉，可变更名称、模型、IP 白名单、到期时间和启用状态。撤销和删除均调用 revoke 接口，必须二次确认；前端不提供重新启用已撤销 Token 的路径。

### 失败处理

沿用 Axios 的登录过期处理及 Element Plus 消息提示。字段校验在提交前完成；后端校验错误显示通用、无敏感信息的提示。加载失败提供重试操作。

## 安全与兼容性

- 永不在列表、详情、编辑默认值或浏览器存储中保留完整 Token。
- 仅使用当前登录用户 JWT；不把 Token ID 作为授权依据，后端负责所有者范围校验。
- 不用前端来判断授权是否有效：状态、IP、到期和模型限制均由后端强制执行。
- 不改变现有聊天、个人中心、计费或 API 请求的行为。
- 页面适配现有浅色/深色主题及移动端布局。

## 测试与验收

测试先行，使用当前仓库能够支持的最小测试方式；若没有测试框架，则不新增依赖，只做构建和浏览器验收并如实记录限制。

验收标准：

1. 可从主导航进入 `/api-keys`，无登录时仍受现有守卫保护。
2. 列表、概览和空状态正确渲染，完整 Token 不会出现在列表中。
3. 创建成功时完整 Token 仅在一次性确认弹窗显示，复制后不持久化。
4. 编辑、撤销、过期状态、模型权限与 IP 白名单在 UI 中正确呈现并调用对应接口。
5. API 错误与加载错误对用户可理解且不泄漏 Token。
6. `npm run build` 通过；若可用，运行对应自动化测试。

## 明确延期

真实调用量、请求审计、密钥轮换、配额/限流、渠道与逻辑模型路由、团队/租户共享、账务和管理员后台，等待后端接口完成后另行设计。
