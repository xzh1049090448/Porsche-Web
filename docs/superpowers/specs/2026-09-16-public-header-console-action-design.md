# 公共页头控制台入口位置调整设计

## 目标

公共页面桌面端页头把“进入控制台”从左侧主导航移到右侧操作区，并放在语言切换和主题切换之后。桌面端顺序固定为“语言 → 主题 → 进入控制台”。

## 响应式行为

- 桌面端（`min-width: 768px`）：左侧主导航只保留产品优势、支持模型、模型价格和关于；控制台入口显示在主题按钮右侧。
- 移动端（`max-width: 767px`）：右侧操作区继续只显示语言和主题按钮；控制台入口保留在折叠菜单中，避免挤压页头。
- 两个响应式入口都指向 `/chat`，任一视口只展示一个可交互入口。

## 可访问性与交互

- 保持现有 `RouterLink`、按钮文案和 `public-console-cta` 语义。
- 移动端入口继续参与菜单焦点循环，并在导航后关闭菜单。
- 桌面端 DOM 顺序与视觉顺序一致：语言按钮、主题按钮、控制台链接。
- 隐藏的响应式入口使用 `display: none`，不进入键盘焦点顺序。

## 实现范围

- 调整 `PublicHeader.vue` 的导航和操作区渲染结构。
- 在 `public-shell.scss` 增加桌面、移动端入口的显示规则。
- 更新公共页头合同测试，验证桌面端位置、移动端位置、唯一可见入口及 `/chat` 路由。
- 不改变控制台路由、文案、主题逻辑、语言逻辑或其他公共页面布局。

## 验收标准

1. 1280px 桌面视口中，“进入控制台”位于主题按钮右侧。
2. 桌面主导航中不再出现控制台入口。
3. 390px 移动视口中，顶部操作区没有控制台入口，展开菜单后可见该入口。
4. 桌面和移动端均只有一个可见且可聚焦的控制台入口。
5. 公共页头合同测试和相关公共页面测试全部通过。
