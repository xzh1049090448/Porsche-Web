# Porsche-Web 全站视觉统一设计

## 背景与目标

Porsche-Web 已具备公共站点、公开模型报价、登录注册、用户控制台和 Root 管理页面，但公共页面与既有控制台的视觉语言不统一。用户确认以 `/Users/xuzhihao/Doubao/chats/2026-09-01/new-chat-1/` 下的五份 HTML 原型为全站视觉母版，并选择“方案 A：完整采用参考体系”。

本次改造覆盖 Porsche-Web 全部路由。Go 后端没有页面，不改接口、数据库、权限或发布行为。改造目标是让公共站点与登录后控制台具有一致的品牌、导航、间距、卡片、表格、表单、反馈和响应式规则，同时保留当前业务数据与安全边界。

## 参考原型与路由映射

| 参考原型 | 页面母版 | 现有页面范围 |
| --- | --- | --- |
| `landing-prototype.html` | 公共站点 | `/`、`/about`、`/terms`、`/privacy`、公共 404 |
| `pricing.html` | 公共报价 | `/pricing`、`/pricing/:modelKey` |
| `dashboard-prototype.html` | 登录后控制台骨架 | `/chat`、`/billing`、`/profile`、登录与注册 |
| `tokens-prototype.html` | 密钥与配置管理 | `/api-keys`、公共模型、公共报价、公共内容、Root 通知 |
| `users-prototype.html` | 用户与权限管理 | `/users`、`/users/:guid` 及相关操作弹窗 |

原型提供视觉和布局依据，不作为业务数据来源。原型中的 `ModelHub`、测试模型、测试价格、`40+`、`100%`、`MIT` 等内容不得硬编码到生产页面；页面继续使用后端发布快照、接口数据和现有国际化文案。

## 共享视觉系统

新增集中维护的语义设计令牌，现有页面不得继续各自定义同义颜色和阴影。浅色主题使用以下基准：

- 主色 `#2563EB`，悬停色 `#1D4ED8`，浅背景 `#EFF6FF`。
- 页面背景 `#F8FAFC`，卡片背景 `#FFFFFF`，边框 `#E5E7EB`。
- 主文本 `#111827`，次文本 `#4B5563`，弱文本 `#9CA3AF`。
- 成功色 `#10B981`；警告、危险、禁用使用独立语义令牌，不用透明度代替状态含义。
- 字体按 `Inter`、系统字体、`PingFang SC`、`Microsoft YaHei` 顺序回退；代码和模型键使用等宽字体。
- 控件与卡片圆角以 8、10、12、16 像素四档表达层级；阴影保持低饱和、小面积，仅用于浮层、Hero 产品预览和可交互卡片。

暗色主题保持相同 DOM、层级、间距和交互，仅替换语义颜色：页面背景 `#0F172A`，卡片与导航 `#111827`，边框 `#273449`/`#334155`，主文本 `#F8FAFC`，次文本 `#94A3B8`，品牌色 `#3B82F6`。未手动选择主题时跟随系统；手动选择继续持久化。两种主题都保留中英文切换。

## 公共站点母版

公共 Header 使用 56 像素高度、半透明白色背景、模糊和细边框。左侧为品牌，桌面端展示优势、模型、价格、文档或关于入口，右侧保留进入控制台、语言和主题操作。移动端折叠导航，按钮触控区域不小于 44 像素。

首页 Hero 采用参考原型的点阵背景、柔色光晕、左右双栏和产品预览卡。左栏渲染已发布标题、介绍和 CTA；右栏只展示安全的产品能力预览，不使用真实对话、密钥、用户数据或未经批准的指标。发布内容缺失时继续显示 `preparing`，不得回退到原型测试文案。

优势区使用三列卡片，模型区使用品牌模型墙，公告与 FAQ 使用双列内容区，底部 CTA 和 Footer 统一收束。移动端改为单列；减少动画系统偏好下停用浮动、位移和页面淡入动画。

关于、条款与隐私页面复用公共 Header/Footer、内容宽度、标题和目录样式。法律页继续显示版本、生效日期、目录与联系方式，净化后的富文本是唯一正文来源。

## 公共报价母版

桌面端使用最大 1600 像素内容区和 260 像素固定筛选侧栏。筛选项包括当前合同支持的供应商、公开分组、能力和端点类型；不恢复已经移除的按次计费筛选。右侧工具栏包含总数、搜索和排序，主体采用紧凑白色表格。

价格只展示输入和输出 Token 单价及其公开单位。缺价、登录后可见、失效和已删除状态继续按现有合同区分，不能用 `0` 或占位价格替代。表格行链接到稳定 `modelKey` 详情页。

小于 768 像素时隐藏桌面侧栏和表格，使用筛选抽屉与价格卡片；分页、搜索和排序保持可操作。模型详情使用返回链接、模型标题、稳定键、双价格卡、元数据描述列表、免责声明和控制台 CTA，并覆盖 404、410、登录后可见及服务不可用状态。

## 登录后控制台母版

主布局按 `dashboard-prototype.html` 重构为顶部产品栏、左侧导航和浅灰工作区。顶部保留品牌、语言、主题、Token/套餐摘要和账号菜单。左侧导航按普通功能与 Root 管理功能分组，仍由当前用户权限决定可见性；视觉隐藏不能替代路由与后端授权。

页面标题区统一包含英文或分类 eyebrow、主标题、说明和右侧主操作。内容区统一使用白色卡片、细边框和低饱和阴影。聊天页面保留适合长文本与流式生成的独立工作区，但其导航、按钮、输入框和状态色使用共享令牌。

套餐与用量、个人中心和登录注册采用控制台卡片与表单规范。登录注册可省略左侧导航，但必须保持品牌、背景、输入框、按钮、错误提示和主题行为一致。

## 管理页面母版

API 密钥、公共模型、公共报价、公共内容和 Root 通知以 `tokens-prototype.html` 为主要依据；用户列表和用户详情以 `users-prototype.html` 为主要依据。

列表页面统一为标题区、搜索筛选工具栏、数据表格、分页和空状态。详情与编辑页面统一为标题、状态徽标、描述列表、分区卡片和底部操作区。创建、编辑、启停、失效、软删除、发布与恢复继续使用现有动作流程。

危险操作使用红色语义色，并保留确认步骤、验证票据、执行状态和失败反馈。Root 专属页面及按钮继续以实际角色判定。公共内容预览保留独立路由和发布快照边界，但套用公共站点视觉，明显标识预览状态。

## 组件与代码边界

实施时按以下边界组织，避免把所有样式集中到单一巨型组件：

- 主题层：语义令牌、基础排版、焦点、动效和响应式断点。
- 公共壳层：Public Header、Footer、移动导航和公共状态容器。
- 控制台壳层：顶部栏、侧栏、移动导航、页面标题和内容容器。
- 数据展示层：筛选面板、搜索工具栏、表格、价格卡、描述列表、状态徽标和分页。
- 交互层：表单控件、对话框、抽屉、通知与确认反馈。

页面只负责组合组件和调用现有 store/API。不得在视觉组件中复制鉴权、价格显隐、字段映射、内容净化或发布逻辑。现有接口契约和 `interface-contract.json` 不因本次视觉改造而变更。

## 状态、错误与安全

所有页面必须继续区分 loading、empty、preparing、ready、not found、gone、forbidden、login required、conflict 和 unavailable。状态组件采用统一图标、标题、说明与重试操作，但保留原有状态码和业务文案含义。

富文本继续使用当前净化结果，不引入 `v-html` 的新来源。外链和危险 URL 规则不变。界面不得显示密码、Token、HMAC、上游密钥或内部价格快照元数据。Root 操作的视觉反馈不得在服务端确认前显示成功。

## 响应式与无障碍

验收宽度至少覆盖 375、768 和 1440 像素。桌面侧栏在窄屏改为抽屉或顶部菜单；表格在移动端使用卡片或允许明确的横向滚动，不能压缩到不可读。对话框不超出视口，内容可滚动，关闭按钮触控区域不小于 44 像素。

所有交互元素必须支持键盘操作、可见 `focus-visible`、合理焦点顺序和 Escape 关闭浮层。对话框使用正确的 dialog 语义和焦点管理；状态变化使用现有适当的 status/alert 语义。文本与背景达到 WCAG AA 对比度，不能只依赖颜色表达状态。

## 实施顺序

本次范围较大，拆成四个可独立验证的实施批次：

1. 共享设计令牌、主题和公共/控制台壳层。
2. 公共首页、内容页、报价列表和模型详情。
3. 登录注册、聊天、套餐与用量、API 密钥和个人中心。
4. 用户管理及全部 Root 管理页面，最后进行全站回归。

每个批次均从同一设计系统继承，不建立并行主题。批次可以分别提交与审查，但在全站回归完成前不得宣称视觉统一任务完成。

## 验收与验证

- 组件合同测试覆盖共享壳层、主题类、路由结构和关键状态，避免只断言 CSS 字符串。
- 现有 `npm test` 全量通过，`VITE_USE_MOCK=false npm run build` 成功，生产 bundle 不包含 Mock 页面或测试数据。
- 浏览器逐页检查全部路由，至少覆盖 375、768、1440，浅色、暗色、中英文、键盘焦点和减少动画。
- 公共页面覆盖准备中、已发布、空、404、410、登录后可见和 503；管理页面覆盖普通用户拒绝、Root 成功、冲突和后端失败。
- 视觉对比以五份参考 HTML 为基准，记录关键页面截图；允许真实内容长度造成自然变化，不允许恢复另一套颜色、圆角、导航或表格体系。
- 性能只记录实际测量结果。本任务不预设 Lighthouse 分数，也不把本地构建成功当作线上性能通过。
- 按仓库完整流程生成 review snapshot，依次完成规格审查和质量门禁；任何审查后代码变化都重新生成 snapshot。

## 非目标与发布边界

- 不修改 Go 后端、数据库、接口字段、HTTP 状态、鉴权或 SSE 行为。
- 不新增模型、价格、宣传数字、法律文本或 P08 正式生产内容。
- 不在视觉改造中更换 Vue、Element Plus、Pinia、Vite 或包管理器。
- 不在实现完成前自动部署。合并、生产发布和带写操作的线上验收作为独立步骤执行。
