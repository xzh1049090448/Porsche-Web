## 1. 问题与目标（Problem Statement）

当前平台已经交付用户名密码认证、可撤销会话、Root 一次性引导和基础角色门禁，但管理员仍缺少完整的用户运营入口；匿名访问者也缺少可直接了解产品、查询模型价格和阅读协议的公共页面。

本次目标是交付两条可分别验收的完整链路：

1. **管理员管理用户**：查找用户 → 查看详情 → 创建或调整账户 → 权限校验 → 保存与安全失效 → 查看审计结果。
2. **访客了解并进入平台**：访问官网 → 查询模型与报价 → 阅读详情和协议 → 注册或登录 → 进入现有控制台。

“完整”指本 PRD 必做范围的页面、后端、数据、权限、异常交互和验收闭环，不等于原 PRD 所有认证、支付及平台模块同时完成。金额额度是用户明确允许的例外：本次交付 Mock 界面与交互，真实余额账本、调额落账和扣费后续实现；其余必做管理动作仍要求真实闭环。

### 1.2 当前实现基线

- 已有用户名认证、服务端会话、Redis 安全失效、基础角色和管理员部分读写接口。
- 当前管理员 DTO 不足以支撑完整用户管理，缺少创建入口与细粒度权限编辑闭环。
- 当前前端以登录后的对话为根页面，不能直接用新增首页覆盖而不处理路由和回跳。
- 当前计费实现包含套餐与每日调用次数限制，不存在可直接套用原型金额的通用余额账本；专业/企业套餐存在不限次数的既有逻辑。
- 本次基线来自本地仓库与已有验收记录，不构成对最新生产数据库或远端代码的实时审计。

## 3. 用户故事（User Stories）

1. 作为管理员，我希望通过用户名、显示名、邮箱或用户 GUID 查找用户，以便快速定位账户。
2. 作为管理员，我希望按角色、分组、状态筛选并保存 URL，以便重复处理运营任务。
3. 作为管理员，我希望查看用户角色、额度、套餐、活动时间和安全状态，以便判断操作影响。
4. 作为管理员，我希望创建普通用户并获得明确结果，以便为客户开户。
5. 作为 Root，我希望创建管理员并分配最小权限，以便分工运营。
6. 作为 Root，我希望查看权限继承、显式允许和显式拒绝，以便理解最终权限。
7. 作为管理员，我希望编辑显示名、分组与允许的套餐配置，以便调整账户服务。
8. 作为管理员，我希望重置用户密码并撤销旧会话，以便处理凭据失窃。
9. 作为管理员，我希望禁用或启用普通用户，以便控制服务访问。
10. 作为 Root，我希望提升或降低用户角色，以便管理职责变化。
11. 作为管理员，我希望预览金额余额的增加、扣减与覆盖流程，以便确认后续真实金额管理的交互；本次明确为模拟。
12. 作为管理员，我希望模拟调额能展示重复提交、失败与冲突状态，以便后续接入真实账本时保持清晰反馈。
13. 作为管理员，我希望查看并撤销目标用户会话，以便处理可疑登录。
14. 作为管理员，我希望软删除用户并看到不可恢复的说明，以便避免误删。
15. 作为 Root，我希望查询已删除用户的最小墓碑记录，以便追溯历史操作。
16. 作为审计人员，我希望按操作者、目标、动作与时间查找记录，以便还原管理行为。
17. 作为普通用户，我希望管理员变更不会导致旧权限继续生效，以便保障账户安全。
18. 作为访客，我希望无需登录查看官网，以便了解平台用途。
19. 作为访客，我希望浏览真实支持的模型和公开价格，以便评估接入成本。
20. 作为访客，我希望按供应商、模型类型和价格筛选，以便快速比较。
21. 作为访客，我希望看清价格单位、币种、计费维度与更新时间，以免误读报价。
22. 作为访客，我希望直接分享模型详情链接，包括名称中含斜杠的模型，以便协作选型。
23. 作为访客，我希望阅读服务协议与隐私政策，以便了解平台规则。
24. 作为用户，我希望登录后回到原目标页，以便继续操作。
25. 作为移动端用户，我希望筛选、表格操作与确认弹窗均可用，以便不依赖桌面设备。
26. 作为内容管理员，我希望预览修改后再发布，以免把草稿暴露给访客。
27. 作为内容管理员，我希望发布失败时旧版本仍可访问，以免官网中断。
28. 作为 Root，我希望恢复上一公开内容版本，以便快速处理错误信息。
29. 作为维护人员，我希望配置、公开数据和管理数据有清晰边界，以免泄露上游密钥和个人信息。
30. 作为测试人员，我希望逐项依据接口、界面和持久化结果验收，以免再次将一期通过等同于全部实现。

## 4. 角色、权限与安全规则

### 4.1 不可覆盖的权限边界

- 访客不是可创建的账户角色；不允许注册或创建 role=0。
- 普通管理员仅可管理普通用户；Root 可管理普通用户与管理员，但不能通过本模块管理自己或其他 Root。
- 不提供创建、升为、降级、禁用或删除 Root 的业务入口；Root 自助资料仍使用个人设置，不得修改自身角色。
- `admin_permissions` 只控制 UI 展示。后端独立核验操作者最新状态、角色、动作权限及目标层级。
- 显式授权不能突破上述硬边界；普通用户不能通过任何覆盖策略获得管理能力。
- 不可见目标统一返回 404；有页面资格但缺少动作权限返回 403。错误正文不得泄露目标敏感信息。

### 4.2 能力目录与默认矩阵

权限模型为角色基线加用户级覆盖，覆盖值有“继承 / 允许 / 拒绝”。拒绝优先于允许，未注册能力默认拒绝。仅 Root 能修改管理员覆盖权限，角色元数据与基线通过版本化种子维护；本次不提供自定义角色创建。

| 能力 | Admin 默认 | Root | 说明 |
| --- | --- | --- | --- |
| users.read / users.create / users.edit / users.enable / users.disable | 允许 | 允许 | 均受目标层级约束。 |
| users.reset_password / users.sessions.read / users.sessions.revoke | 拒绝 | 允许 | Root 可按需授予管理员。 |
| users.plan.change / users.group.change | 拒绝 | 允许 | 涉及真实服务权益，独立控制。 |
| users.quota.adjust | 拒绝 | 演示场景可模拟允许 | 预留金额权限；本次仅在隔离 Mock 中演示，无生产生效动作。生产能力目录标记 unavailable，不能因角色为 Root 自动启用。 |
| users.delete / users.deleted.read | 拒绝 | 允许 | 可向管理员授权，但仍只能处理低角色用户。 |
| users.promote / users.demote / users.permissions.write | 不可授予 | 允许 | 仅 Root；提升只允许 user→admin，降级只允许 admin→user。 |
| users.audit.read | 允许 | 允许 | 只读取有权管理目标的审计；软删目标还需 deleted.read。 |
| groups.read | 允许 | 允许 | 用于筛选及分组选择。 |
| groups.write | 不可授予 | 允许 | 创建/停用业务分组，不配置上游路由或倍率。 |
| public_content.read / public_content.edit / public_content.preview | 拒绝 | 允许 | 可独立授权给管理员，不因此获得用户管理权。 |
| public_content.publish / public_content.rollback | 拒绝 | 允许 | 可独立授权；发布者与编辑者可为同一人。 |

权限编辑器按模块展示三态设置，同时展示最终生效值和来源。保存必须提交已读取版本；版本冲突返回 409，不覆盖他人修改。未知资源、动作或试图授予 Root 专属能力均拒绝。

权限或角色变化成功后，新请求必须采用新授权结果；不得仅等待 15 分钟 JWT 自然过期。权限变更、升降级统一递增安全版本并撤销目标会话。登录、刷新和本人资料响应返回同一口径的能力集。

## 5. 管理员用户管理

### 5.1 页面与列表

入口为 `/users`，详情为 `/users/:guid`。主视图为面包屑、标题/说明、筛选工具栏、用户表格及分页。

- 搜索：用户名、显示名和已有邮箱；全数字关键词额外匹配 GUID，不匹配或返回内部主键。
- 筛选：角色、业务分组、启用/禁用/已删除；默认排除已删除。分组不是套餐，不从套餐名称伪造分组。
- 排序：GUID、用户名、分组、创建时间、最后登录时间；默认 GUID 倒序，非法排序回退默认；同值以 GUID 排序保证稳定。金额排序仅在完整模拟列表中演示，生产不允许用局部 Mock 数字排序真实分页结果。
- 分页：20/50/100 条，最大 100；关键词变化或筛选变化重置第一页；状态写入 URL 查询参数。
- 搜索请求取消或序列化，旧响应不能覆盖新查询；删除导致页码超出时回退最后有效页。
- 表格列：用户 GUID、用户名、显示名、分组、套餐、金额额度、角色、状态、最近登录、操作。金额列在演示模式展示“余额 + 已用 + 币种 + Mock 标记”；生产显示“金额功能未接入”，不显示虚构余额或用 0 代替缺失值。
- GUID 与额度数字使用等宽字体。没有邮箱、昵称或登录记录时显示“未设置/从未登录”，不编造内容。
- 顶部总数只统计当前操作者可见数据，禁止通过计数泄露更高角色或隐藏用户。
- 不提供无筛选的批量导出、批量重置密码或批量删除，避免扩大本次风险面。

### 5.2 详情

详情分区：基本资料、服务权益、安全与会话、权限（Root 管理管理员时）、管理审计。

基本资料含 GUID、用户名、显示名、已存在的联系信息、角色、状态、创建/更新/最后登录时间。默认不展示证件、密码哈希、令牌、内部主键、Refresh 摘要或凭据 SID。

会话列表展示会话 GUID、登录方式、IP、UA、创建/活跃/到期时间及撤销状态；仅有独立会话读取权限时请求数据。IP/UA 仅用于安全排查，不复制到公共数据或营销统计。

### 5.3 创建用户

- 字段：用户名、显示名、初始密码、确认密码、角色、分组、套餐。初始金额字段仅在隔离 Mock 创建表单中演示，生产创建不提交金额字段。
- 用户名复用现有服务端校验与永久唯一约束；显示名可为空，最大 64 字符；用户名创建后不可修改。
- 密码 8–20 字符，复用现有强度和弱密码校验；确认密码只在前端比较，不落库。
- Admin 仅可选择普通用户；Root 可选择普通用户/管理员。Root 选管理员时可配置权限覆盖。
- 默认启用，默认分组 `default`，默认免费套餐，实际调用限制保持现有新用户政策；本次不赋予真实初始金额余额。
- 套餐超出默认值时额外要求相应权限；不得以创建请求携带金额字段的方式绕过未实现的账本能力。
- 创建、初始化权限/权益、写审计为一个可验证原子业务动作；重复提交不得产生第二用户。用户名冲突返回明确冲突，不泄露旧用户资料。
- 创建成功显示 GUID 与用户名，不在成功列表、审计或日志再次展示密码；本次不发送密码邮件，也不伪装已有找回密码功能。

### 5.4 编辑、密码重置与服务权益

- 普通编辑只允许显示名等声明的可变字段；用户名、GUID、角色和安全版本不可通过通用编辑修改。
- 套餐、分组分别使用真实专属动作与权限；金额调整使用隔离 Mock 交互，不作为真实账户编辑提交。套餐变更不是付款，不生成“已支付”记录，审计标记“管理员授予/调整”。
- Admin 不可改目标为管理员；角色升降必须走 Root 专属动作。
- 密码重置要求输入新密码与确认密码、操作原因，二次确认提示所有会话将失效；不返回旧密码，不自动登录目标。
- 密码重置、分组、套餐或允许模型范围变更均撤销目标会话并清理相关授权缓存；不能保留缓存中的旧权益。
- 对话、API Key、调用路径必须重新使用最新用户状态与权益。重置密码不自动删除已有 Gateway API Key，但禁用与软删后全部调用凭据都必须不可用。

### 5.5 启停与角色动作

- 禁用：要求原因与二次确认；撤销全部会话，发布安全否决并阻断已有 API Key 调用。
- 启用：不恢复旧会话。禁用前已经独立撤销/过期的 Key 不复活；仍有效的 Key 是否能用以最新账户状态和其自身状态判断。
- 提升：Root 将普通用户提升为管理员，可同时指定覆盖策略；默认采用矩阵的最小基线。
- 降级：Root 将管理员降为普通用户，删除其覆盖策略的有效性、撤销会话并清除权限缓存；历史审计保留。
- 所有动作执行时重新核验操作者和目标最新状态，不能依赖打开弹窗时的旧角色。并发冲突返回 409 并提示刷新。

### 5.6 金额额度（本次 Mock）与业务分组

**已确认定义**：额度是金额余额，不是每日调用次数或 Token 数。金额模块本次只实现可验收的模拟界面和交互；不实现真实资金存储、充值、冻结、扣费、退款或对账。

#### 5.6.1 金额展示与模拟调整

- 展示可用余额、累计已用金额、币种和最近模拟调整记录；“已用”指模拟消费，不因管理员扣减余额而增加，不与真实 Token 用量混算。
- 演示固定使用 CNY，输入最多两位小数，以整数分或精确十进制计算；这只是样例约定，不决定后续生产币种、精度或汇率。模型微额计费精度另行设计。
- 增加/扣减输入正金额；覆盖输入非负金额，允许覆盖为 0。扣减超过当前模拟余额整体拒绝，不产生负数、不截断为零；非法数值、超精度及超过演示上限拒绝。演示输入和结果上限均为 CNY 999,999,999.99，后续真实限额独立评审。
- 调额弹窗包含模式、金额、原因、调整前/后余额与二次确认。提交成功固定提示“模拟调整完成，不影响真实账户”，不能使用“充值到账”等文案。
- 用固定测试夹具演示成功、加载、余额不足、校验失败、超时、版本冲突和重复提交；相同模拟请求重复发送不重复更新演示余额。
- 模拟操作记录展示动作、操作者样例、原因和前后金额，持续标记“Mock”；不能写入正式资金流水或管理审计。

#### 5.6.2 Mock 隔离与生产边界

- 仅在开发/测试的独立演示入口启用金额 Mock，使用合成用户和内存夹具；不导入生产用户数据，不复用真实用户 GUID，不请求真实管理写接口。
- 模拟金额、初始金额及权限验证全部在该入口模拟；不得收集真实管理员密码来验证模拟调额，也不调用真实操作票据接口。
- 生产用户列表/详情保留金额区域的“未接入”提示，调额及初始金额输入不开放；不能通过查询参数、本地存储或前端开关开启生产 Mock。
- 生产不注册可执行的金额调整服务。旧接口、新 actions 入口或伪造请求携带调额动作/金额字段都应按未支持能力拒绝，不能返回模拟成功。
- 刷新演示入口可重置夹具，界面需明确提示；禁止把模拟余额持久化到正式数据库、浏览器中的真实账户状态或生产缓存。
- Mock 金额为 0 或调整为 0 均不控制实际请求；现有每日调用次数、套餐、API Key 和实际消费行为保持不变，也不从历史调用量生成开账余额。

#### 5.6.3 后续真实金额能力

后续单独设计币种与精度、开账/迁移、不可变账本、余额及预占、用量计费与价格版本、充值/退款、并发扣减、幂等与对账、权限复核和审计。正式接入前需以真实集成验收替换 Mock 验收，不可仅切换数据源后宣称完成。此处只记录依赖，不是本次实现任务。

#### 5.6.4 业务分组（本次真实实现）

- 分组目录支持 Root 创建、改显示名和停用；键创建后不可修改，`default` 不可停用。有未删除用户引用的分组不能停用，先迁移用户。
- 组是运营标签，不自动产生模型访问权、价格倍率或套餐权益；这些属性必须独立显示，防止同名误用。

### 5.7 墓碑软删除（已确认）

删除弹窗必须输入目标用户名并填写原因，固定说明：“账户不可恢复、用户名不可再次注册、所有会话与调用凭据将失效；财务与必要审计记录按既定策略保留。”

业务处置：

1. 核验最新操作者权限与目标层级，拒绝 Root、自己、同级/更高角色。
2. 设置 `is_deleted=1`、更新审计字段、递增安全版本、逻辑撤销会话与调用凭据、使权限覆盖失效。
3. 清理密码哈希、联系资料和非必要敏感个人资料，保留用户名占用、GUID、关联主键及必要墓碑元数据。
4. 订单、必要用量及审计不被级联物理删除；墓碑视图不重新暴露已清理资料。
5. 拒绝以该账户身份登录、刷新、管理或调用模型。以其他操作者身份针对该账户，仅允许经授权的墓碑/审计读取及删除结果确认，禁止其他变更；反复确认同一删除结果不重复产生清理副作用。

本 PRD 不规定法定保存期限或宣称满足特定法规；数据生命周期政策需另行审定。本次不新建自动物理清理任务，不清除备份。

已删除视图只读，不提供恢复、启用、编辑、调额、升降级或物理删除。管理读取需要 `users.deleted.read`，且仍受目标角色层级限制。

### 5.8 审计与敏感动作验证

- 记录操作者、目标 GUID、动作、原因、时间、请求 ID、脱敏前后值、成功/失败结果；密码类字段仅记录“已重置”，不记录明文、哈希或长度特征。
- 用户变更与成功审计同事务；审计写入失败不得返回成功。安全拒绝记录脱敏事件，但不能借此泄露隐藏用户。
- 除目标详情内审计外，提供 `/users/audit` 管理审计页，支持操作者、目标 GUID、动作和时间范围组合筛选；查询范围及总数始终只包含当前有权查看的目标，软删目标另需 deleted.read。该静态路由必须优先于用户详情参数路由匹配。
- 密码重置、角色/权限变更、软删除需要操作者重新验证当前密码，产生有效期 5 分钟、绑定当前会话/动作/目标的单次操作票据；票据只在内存短暂持有，不写日志或浏览器持久存储。金额 Mock 不调用该真实验证链路。
- 该票据是本模块的密码复核机制，不声称已经实现原 PRD 的 Passkey Security Proof；验证失败统一提示、按账户/IP 限流，不透露内部状态。
- Redis 或 MySQL 异常时敏感操作失败关闭，不可展示成功。失效栅栏与数据库状态需要可重试恢复机制，不允许“已禁用但旧 Key 仍可调用”。

## 6. 公共页面体系

### 6.1 路由与兼容

| 路由 | 访问规则 | 功能 |
| --- | --- | --- |
| `/` | 所有人 | 官网首页，不自动向已登录用户隐藏。 |
| `/pricing` | 默认公开；可统一设为登录可见 | 模型价格目录。 |
| `/pricing/:modelKey` | 与价格目录一致 | 单模型报价与能力详情。 |
| `/about` | 所有人 | 品牌、产品定位和联系渠道。 |
| `/terms`、`/privacy` | 所有人 | 有版本号和生效日期的正式内容。 |
| `/login`、`/register` | 保持现有认证行为 | 风格统一，注册受现有开关控制。 |
| `/chat` | 登录用户 | 原根路由对话功能。 |
| `/users`、`/users/:guid` | 管理员且具备对应能力 | 用户管理。 |
| `/system-settings/site`、`/system-settings/public-content` | 对应内容权限 | 站点及公共内容管理。 |

- `/profile`、`/billing`、`/api-keys` 的既有行为与登录回跳保持不变；不创建另一个平行的 Key 或计费模块。
- 旧的“登录成功进入 `/`”逻辑改为默认 `/chat`；已收藏 `/` 的用户将看到官网，官网始终提供“进入控制台”。此路径语义变化需写入发布说明。
- 模型 URL 使用服务端分配的稳定、不含斜杠的公开 `modelKey`，与原始模型 ID 一对一关联；模型真实名称可含 `/`，不能直接按多段路由拆解它。
- 回跳仅允许站内合法路径，拒绝绝对外部 URL、协议相对 URL 和编码绕过；不能形成开放重定向。
- 未知公共路径展示真实 404；无权限管理路径显示 403。禁止所有未知路径无差别跳回首页。
- 价格登录可见时，页面 HTML、公开 API、缓存、sitemap 和预渲染快照均不得暴露被保护报价。导航显隐与接口访问策略分别校验。

### 6.2 官网首页

顺序：固定顶栏 → 双栏 Hero → 功能优势卡片 → 支持模型 Logo 墙 → 公告/FAQ → CTA 横幅 → 页脚。

- 顶栏包含 Logo、优势/模型锚点、价格、已配置文档链接、关于、进入控制台。
- Hero 包含产品名、标题、副标题、主 CTA 与产品预览卡；预览卡可为明确标记的演示内容，不能冒充真实用户对话。
- 优势最多 8 项，模型墙只使用已发布且获准公开的模型/供应商品牌。
- 原型中“40+、100%、MIT”等属于示例，必须用可证明事实替换；无可核实来源时隐藏，禁止直接照搬。
- 公告展示有效且已发布条目；弹窗按公告版本在本地记录已读，关闭不影响其他内容浏览。
- CTA：未登录进入登录页并回跳 `/chat`；已登录直接进入 `/chat`；注册关闭时不出现“立即注册”失效入口。
- 文档、状态页或联系链接未配置则不渲染入口，禁止 `href=#` 假链接。

### 6.3 模型价格列表

- 桌面布局：左侧 260px 筛选卡 + 右侧工具栏、价格表和分页；移动端筛选抽屉与卡片列表。
- 搜索模型名称/公开别名；筛选供应商、公开展示组、定价类型、端点类型。公开展示组与内部用户分组严格分离。
- 排序支持默认、名称、输入价、输出价；只能在相同币种/单位/定价类型的可比集合内按数值排序，混合单位提示先筛选，不做伪比较。
- 默认每页 20，支持 50/100；筛选、排序和分页写入 URL。可选收藏仅保存公开 modelKey，不保存认证信息。
- 表格字段：模型、定价类型、输入/输出或单次价格、币种与计价单位、供应商、上下文、端点类型、公开展示组、更新时间。
- 没有价格显示“价格未发布”，不显示 0 或“免费”；已下架模型从列表移除。明确的免费价格必须来自发布数据。
- 无结果、首次空目录、网络失败、数据更新中分别展示状态，错误时有重试，不自动回退成原型示例数据。

### 6.4 模型详情与报价来源

- 展示模型 ID、供应商、说明、能力标签、上下文、支持端点、公开限制、完整多维报价、币种/单位、生效时间及“进入控制台”入口。
- 价格数据来自服务端发布目录；前端不能用散落常量或供应商示例自行计算价格。
- 报价按“每百万输入/输出 Token”“每请求”等维度存储；缓存、图像、音频或阶梯规则仅在有完整数据时显示，不能用 0 补缺失值。
- 当前实际按次数/套餐控制服务，不等于已经按 Token 价格扣款。本稿价格页统一标注“模型参考报价，非自动扣费承诺；账户实际服务权益以套餐及控制台为准”。若改成正式结算价，发布前必须纳入实际账单一致性验收。
- 参考报价仍需来源说明、审核人和更新时间；不展示未授权的上游成本、内部折扣、渠道地址或密钥。
- 未发布/不存在的 modelKey 返回 404；历史已发布但下架的 modelKey 返回 410 与下架说明，不再展示失效报价；改显示名不改变稳定链接。
- 目录不可用与模型不可调用是不同状态；单纯价格可见不授予调用权限。模型详情不执行真实付费请求。

### 6.5 关于、协议与隐私页面

- 关于页包含产品介绍、运营主体提供的信息及联系入口，不编造企业资质或承诺。
- 协议/隐私页展示标题、版本、生效日期、正文、目录和联系方式；正文由运营/相关负责人审核后发布，本 PRD 不生成或替代法律文本。
- 首次上线公共体系前必须有已审核发布的协议和隐私内容；缺失时作为发布阻塞，不生成空白“正式协议”。
- 登录注册页及页脚提供固定可达链接；原业务若要求勾选同意，保留并记录对应版本，不在本稿暗中新增追踪用途。

### 6.6 公共内容管理与发布

仅实现支撑本次公共页面所需的站点/内容设置，不扩展成全量系统设置中心。

- 站点：名称、Logo 引用、页脚、联系信息、文档链接、导航排序与显隐。
- 首页：Hero 文案、演示卡说明、优势、模型展示、公告、FAQ、CTA。
- 页面正文：关于、协议、隐私；支持受限 Markdown/安全富文本，不执行脚本、事件属性或任意嵌入代码。
- 模型目录：公开标识、与现有模型 ID 的映射、公开展示字段、报价维度、展示状态；公开展示配置不修改路由、渠道或模型权限。
- 状态为草稿→已发布；修改已发布内容先创建新草稿。预览必须鉴权、`no-store`、`noindex`，不生成匿名可枚举草稿地址。
- 发布为一个原子版本：相关导航、页面和报价必须来自同一快照；提交时校验引用、必填值、链接、安全内容、价格单位及版本冲突。
- 每次发布记录操作者、时间、版本、内容摘要；保留最近 20 个可恢复发布版本及必要审计，不在业务请求中物理删除历史记录。
- 恢复历史内容通过“生成一个新发布版本”完成，不回滚数据库结构或恢复用户权限。
- 并发编辑和发布使用版本校验，冲突 409；网络重试不重复发布。失败时继续服务上一个有效版本。
- 公共 API 和 CDN/预渲染内容在发布后 60 秒内可见新版本；访问控制从公开改为登录可见必须同步失效公开缓存，无法确保时拒绝该次模式切换，不能留泄露窗口。
- 图片只允许已审批来源或现有受控上传地址；本次不实现任意 URL 抓取或远端图片代理，防止 SSRF。外链仅允许 http/https，禁止 javascript/data 等可执行方案。

### 7.2 页面细节

- 用户管理：沿用白色表格卡片、搜索排序工具栏、右侧蓝色“添加用户”；危险动作使用红色并收进“更多”，避免密集误点。
- 详情采用分区或抽屉，但 `/users/:guid` 必须可直接进入；返回列表保留筛选和滚动状态。
- 公开首页采用固定毛玻璃顶栏、淡色渐变圆与点阵、左右 Hero、浮动模型标签、四列优势卡及深色精简页脚。
- 价格页沿用筛选标签云和等宽价格列，明确显示计费单位；不能因追求原型相似隐藏价格说明。
- 新页面适配现有亮/暗/跟随系统主题；浅色以原型为基准，暗色使用语义 Token，不反色图片、不退化可读性。
- 沿用现有中文/英文能力；本次不把原文提及的七语言当作已交付。所有新增文案可翻译，日期按界面语言展示并提示统计时区。

### 7.3 通用状态和可访问性

- 每个数据页必须有加载骨架、空态、失败重试、403、404及提交中状态；权限不足不显示成功空表。
- 弹窗支持键盘、焦点锁定、关闭后焦点恢复；表单错误定位具体字段，提交失败保留非敏感输入。
- 真实危险动作不乐观更新；服务端确认成功后更新页面。网络超时提示“结果待确认”，通过幂等结果或重查确认，不诱导重复操作；金额 Mock 由模拟适配层返回显式模拟结果，不等待或请求真实资金服务。
- 提交中防重复点击；列表只读刷新不丢筛选；错误提示带请求 ID，不输出数据库原文或凭据。
- 断点：≥1280px 桌面；768–1279px 折叠侧栏；<768px 抽屉导航、卡片列表与可用筛选。
- 过渡 150–400ms；遵守减少动态效果设置；不得给 body 添加 transform 破坏 fixed 顶栏。

## 8. 实现决策与接口边界（Implementation Decisions）

### 8.1 模块边界

账户管理负责状态与业务动作；授权模块负责能力目录与最终判断；金额 Mock 适配层只处理合成演示数据，不实现正式额度服务；审计模块负责真实脱敏事实；公共目录只输出公开数据；内容发布模块负责版本与可见性；前端共享设计 Token 和现有认证客户端。

这些模块必须可通过外部行为独立测试。业务判断不能只散落在页面按钮或 HTTP handler 中。

### 8.2 API 产品契约

下表是新增能力的拟定接口。已有接口不得无版本直接改变响应形状；详细 DTO 在开发前冻结。

| 接口族 | 能力 |
| --- | --- |
| `/admin/v2/users` | GET 返回 items/total/page/page_size；POST 创建用户。 |
| `/admin/v2/users/:guid` | GET 详情；PATCH 仅编辑声明的基础字段，携带版本。 |
| `/admin/v2/users/:guid/actions` | POST 显式动作：启停、升降级、密码重置、套餐/分组变更、软删除。本次不支持金额调额，伪造调额动作必须拒绝。 |
| `/admin/v2/users/:guid/sessions` | GET 会话；专属撤销动作支持单个 GUID 或全部会话。 |
| `/admin/v2/users/:guid/audit-events` | GET 目标审计，分页、权限及时间过滤。 |
| `/admin/v2/user-audit-events` | GET 跨可见目标审计，按操作者/目标/动作/时间筛选，分页与总数均经过权限过滤。 |
| `/admin/v2/action-verifications` | POST 操作者密码复核，签发单次动作票据。 |
| `/admin/v2/authz/catalog` | GET 角色基线、资源动作目录；不返回内部策略主键。 |
| `/admin/v2/users/:guid/permissions` | GET/PATCH 管理员覆盖策略，Root 专属。 |
| `/admin/v2/groups` | GET 可选目录；Root 创建、编辑及停用动作。 |
| `/api/public/site` | GET 仅已发布的安全站点与导航配置。 |
| `/api/public/pages/:slug` | GET home/about/terms/privacy 的已发布内容。 |
| `/api/public/models`、`/api/public/models/:modelKey` | GET 公开价格目录与详情，受价格可见性策略保护。 |
| `/admin/v2/public-content` | 草稿、预览、版本、发布与恢复操作，逐动作校验能力。 |

- 新对外用户及会话标识使用字符串 GUID；数据库内部 id、凭据 SID 不进入常规资源 URL。
- 现有 `/admin/users` 不因 v2 出现而失去安全校验：旧读写入口也必须调用同一授权及安全失效策略，不能成为绕过细粒度权限的后门。
- 现有认证路径、Cookie 名称与安全属性保持不变；新公共 GET 不强制刷新认证，管理请求继续使用当前 Access/Refresh 机制。
- 输入字段采用允许清单；拒绝越权字段而非静默修改。400 为输入非法、401 未认证、403 禁止、404 不可见目标、409 冲突、429 限流、503 依赖不可用。
- 保持项目既有错误封装；返回可读且脱敏的消息与请求 ID，前端不得依赖字符串匹配判断授权。

### 8.3 数据与一致性

- 用户分组、权限策略/角色目录、管理审计、公开模型与价格维度、草稿/发布版本需要明确持久化设计；不以现有字段同名为由假定已经存在。金额 Mock 不新增正式余额列、资金账本或调额流水表。
- 新表必须包含内部 id、唯一雪花 guid、四个审计字段、`is_deleted`；用户关联使用内部 user_id，持久化时间为 BIGINT Unix 毫秒，状态枚举为稳定 INT。
- Casbin 策略持久化必须适配项目软删除和审计规范：失效策略不再参与授权，不以库默认物理删除行为绕过约束。
- 价格使用精确十进制文本或定点表示，不能靠二进制浮点累加；次数为有界整数。此规则不授权重写既有订单金额数据。
- 迁移只新增前向版本，不修改已发布 checksum，不通过启动时 AutoMigrate 修改生产数据。
- 历史用户默认归入 default 分组，保留用户名、角色、Key、订单、调用计数及套餐行为；角色基线变化必须有权限影响清单。
- 跨 Redis/MySQL 的安全失效需要持久化待处理状态与重试策略；成功响应前必须达到“旧权限/凭据不可再使用”的可验证条件。

### 8.4 公共数据、SEO 与性能

- 公共 DTO 采用独立允许清单，不复用管理 DTO 删除几个字段后直接返回；禁止用户信息、私有组、供应商密钥和内部渠道信息泄露。
- 首页、价格及正文页提供标题、描述、canonical、社交分享元数据与有效索引内容；采用预渲染或等效方案，不能只有空 SPA 容器等待爬虫执行。
- 草稿、管理页、登录页和受保护价格不进入 sitemap；公开详情下架后同步更新 sitemap 和状态。
- 10 万用户测试集、并发 10、每页 20 的列表查询服务端 P95 目标 ≤500ms；测试报告注明硬件与冷热缓存，未达标须记录而非隐藏。
- 内容发布一致性见 §6.6；静态资源带内容哈希，HTML 不能长期缓存旧入口。公共页不得强迫下载全部管理模块。

## 9. 测试与验收（Testing Decisions）

所有必做模块都需要测试；以下为本稿建议的验收范围，评审通过后作为开发门禁。测试检查用户可观察结果、接口与数据库/缓存事实，不只检查某函数被调用或某按钮存在。

沿用现有隔离 MySQL/Redis 集成测试、前端单元与 HTTPS 浏览器验收方式。除 D02 明确批准的金额 Mock 外，Mock 仅用于开发与故障注入，不替代真实集成；不读取生产凭据来运行自动化测试。金额模块本次报告为“Mock 验收通过/失败”，真实金额能力标记“未实现”，不混为一个通过状态。

| 编号 | 验收场景 | 必须满足 |
| --- | --- | --- |
| A01 | 普通用户直达管理页及接口 | 无管理数据泄露；界面与接口均拒绝。 |
| A02 | Admin 管理 Root/其他 Admin/自己 | 全部管理动作拒绝，计数与详情不泄露隐藏目标。 |

## 10. 交付顺序与发布边界

1. **需求评审**：D02 已确认金额 Mock；评审其余建议决策，冻结真实功能与模拟功能的分界及能力矩阵。
2. **管理底座**：迁移、DTO、权限、审计与账户动作，先通过真实集成测试。

4. **公共数据与内容发布**：独立完成安全公开 DTO、版本/预览/发布及报价管理。
5. **公共页面与路由切换**：视觉对照、旧入口回归、SEO、缓存和匿名访问验证。
6. **正式验收与发布批准**：报告逐项标明通过/失败/阻塞；记录前后端版本、迁移版本与恢复步骤后，由用户另行批准部署。
