# 前端工程开发规范

## 当前基线与工具

当前 Vue 3 + JavaScript + Vite 6 + npm。保留现有代码格式、依赖、构建配置及锁文件。TypeScript strict、ESLint/Prettier/Stylelint、pnpm 和 Git Flow 为用户模板中的候选目标，尚未启用；迁移必须另开经授权的任务，不能借规范搭建自动安装或切换。

## 实现规范

- 复用组件、API、Pinia store、GUID 工具；组件单一职责，拆分依据职责和维护成本，不设无依据行数门槛。
- 组件名 PascalCase，变量 camelCase，常量 UPPER_SNAKE_CASE。公共函数及复杂逻辑添加必要 JSDoc/注释；未来 TypeScript 任务启用 strict 并避免滥用 any。
- Props 类型、默认值、事件名与参数明确；交互组件按需求支持受控/非受控，附使用和边界说明。
- 页面负责组装，服务层封装通信，Pinia 管理共享状态；禁止在 UI 复制鉴权和字段映射逻辑。
- 按仓库流程保持单功能推进；提交获授权时采用 Conventional Commits。不擅自更换分支策略或推送。

## 验证和性能

- 单元回归：npm test；业务变更按授权执行 npm run build 和浏览器 smoke。init.sh 会安装依赖，执行前核对范围。
- 安全：Markdown/HTML 输出清洗、XSS、CSRF、点击劫持、敏感信息、路由权限、依赖漏洞；缺少依赖审计证据须标注，不将零扫描视作安全。
- 路由懒加载、按需加载、长列表虚拟化及 CDN/缓存按测量选择；本次不修改部署。
- 候选性能目标：4G 首屏小于 2 秒。开发前双方明确首屏采用何指标（例如 LCP）、设备、带宽/延迟、冷暖缓存、样本数和统计口径，另约定交互延迟阈值；未约定不能判通过。
- Lighthouse 如可用记录版本、URL、环境、指标与原始报告；不可用记 SKIPPED。禁止虚构分数或把本地结果当线上证据。
- Quality Gate 对最终差异独立复核；全体已约定核心用例必须执行且通过，修复后重新验证。只读角色不得因测试生成文件而突破权限。
