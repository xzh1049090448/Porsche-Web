# 前端数据交互规范

与后端数据库约束对齐，但不把数据库类型直接当作每个 API 的序列化类型。数据库文档位于后端仓库 docs/conventions/database-standards.md；跨仓库使用前核实目标工作树。

## 数据类型

- 业务 GUID 始终保留字符串，禁止 Number/parseInt 转换及自行生成；内部数据库 id/user_id 不作为对外标识。模型目录 ID 仍按模型契约处理，不套用业务雪花校验。
- 后端持久化时间为 UTC Unix 毫秒 BIGINT；API 可能按 DTO 返回毫秒或 RFC3339，逐字段记录。显示可按明确的用户时区转换，传输不得二次偏移或混淆秒/毫秒。
- 后端持久化枚举为稳定 INT；API 按 DTO 契约可能返回整数或可读名称。禁止统一强制字符串枚举，维护明确映射并处理未知值。
- 请求和响应可以是不同 DTO；列表/详情复用共同语义，不提交服务端只读、归属和审计字段。

## 存储和安全

目标：Access Token 仅内存，Refresh 使用服务端 HttpOnly/Secure Cookie；浏览器自管加密不能替代 HttpOnly 或消除 XSS 风险。不新增凭据到 localStorage/sessionStorage/日志。

历史main曾将Token存入localStorage。当前M2复用用户名分支并实施内存认证加固；按最终代码和验证报告判断修复状态，不依据旧main描述判定。允许存储不含身份信息的跨标签epoch/pending/退出标志；它们不是登录凭据。

缓存设置过期与用户隔离，注销清理；字典/枚举以服务端合同为准，不擅自更改稳定含义。对话删除遵守既有逻辑删除契约，不能指挥后端物理删除数据。

## 评审清单

- [ ] GUID 无精度损失，空值和无效值行为有验证。
- [ ] 时间单位、展示时区和传输类型逐字段明确。
- [ ] 枚举与未知值映射同后端 DTO 一致。
- [ ] Token、敏感数据、缓存和退出登录行为经过审查。
- [ ] 不暴露内部 ID、不修改只读字段、不跨用户复用缓存。
